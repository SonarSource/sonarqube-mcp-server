# Architecture workflows and API behavior

[Tool reference and setup](../README.md#architecture). This document contains the detailed output, validation and recovery behavior for Architecture workflows.

**Availability:** Architecture tools are disabled by default; enable `architecture` in `SONARQUBE_TOOLSETS` for stdio or HTTP. SonarQube Cloud requires a Team or Enterprise plan and exposes all targets (`current`, `intended`, `directives` and `findings` on `architecture_get`; `intended` and `directives` on `architecture_set`). SonarQube Server exposes only `intended` on `architecture_get` and `architecture_set`; unsupported targets and parameters are omitted from Server schemas and rejected at execution.

On Server, intended architecture reads and writes require the public `/api/v2/components/projects` lookup and `/api/v2/architecture/project-intended-architectures` APIs. Unavailable features or endpoints fail when called; use the tool schema advertised by the running MCP build.

- **architecture_get** - On Cloud, read current dependencies, intended groups and constraints, project directives, or deviations, flaws and smells with their details. On Server, read intended groups and constraints. Findings are read from the latest main-branch analysis. Current views show at most 150 nodes; narrow the view with `component` or `language`. Omitted siblings may remain undiscoverable, so a capped view is not a complete graph export. `omittedNodes` counts nodes excluded by limits within the requested component/depth, not deeper descendants. Every returned node includes `descendants` and `truncated` navigation metadata; the five `drillDown` entries are suggestions. Selecting a leaf returns an explanatory message.

  Directive pages return `view: "summary"`: all matching page entries and their exact operation keys, origin and IDs, without descriptions. `descriptionOmitted` indicates whether a description is stored; use `directiveId` for the complete record. Summaries are not full exports. The default remains 50; pages are limited to 50 entries. Requests above 50 fail instead of being silently clamped. When reducing `pageSize`, restart at `pageIndex: 1` and continue paging. Backend totals are unchanged. This limit applies only to MCP list reads; write preflight and CLI pagination are unchanged. Backend pages still contain full records; this reduces tool output, not API transfer. Long keys and large pages can still produce large responses.

  For a focused dependency query, supply both `from` and `to` with exact current keys, without `component`. The query includes descendants and preserves direction. `depth` defaults to 1 (direct children, retaining leaves); use a returned pair or increase depth for detail. Matching leaf-level dependencies are aggregated before pagination, independent of the overview node cap. Ancestor/descendant aggregate rows are omitted; increase depth to inspect internal dependencies. Each page returns dependency keys/weights, `paging` metadata including the total, and `revision`; compare revisions before combining pages and restart if changed. Specify `language` if the pair matches multiple graphs. Container-level relationships overlapping both selected subtrees are rejected in this mode. Unrelated relationships are ignored. Matching graphs reject duplicate node IDs or ambiguous keys because complete dependency pages require unambiguous edge identities; the overview is best-effort. Counts limit rows, not bytes or tokens.

  Malformed or incomplete Architecture responses are reported as API errors with validation details. These errors do not infer an unsupported deployment or recommend an upgrade. Authentication, permission, missing-resource and server errors retain their own context; empty results alone are not errors. These diagnostics do not probe versions or make additional requests.

  Current graph reads are limited to two concurrent calls per tool instance. Additional calls wait up to five seconds for capacity before returning a busy error. Each accepted call still downloads and processes the full selected graph.

  Parameters:
  - `target` - Cloud: `current`, `intended`, `directives` or `findings`; Server: `intended` - _Required Enum_
  - `projectKey` - The project key - _Required String_ _(Ignored when `SONARQUBE_PROJECT_KEY` is defined)_
  - `organization` - SonarQube Cloud organization key when none is configured; required for `current` and `findings` - _Optional String, Cloud only_
  - `component` - Exact returned current node key (Java: `module:package`), intended group key (labels joined by `/`), or findings node key; no wildcards; top level when omitted - _String_
  - `depth` - Levels below the start, integer 1–64 (default: 1 for `current`, all for `intended`) - _Integer_
  - `language` - `java`, `cs`, `js`, `ts` or `py`; current/intended/findings only - _String_
  - `directiveId` - Directives only (Cloud only): full record, including description, by UUID; cannot be combined with paging - _String_
  - `category` - Findings only (Cloud only): `deviation`, `flaw` or `smell` - _Enum_
  - `type` - Findings only (Cloud only): `structuralDeviation`, `relationshipDeviation`, `tangle`, `oversizedComponent`, `weakTangle` or `splitResponsibility` - _Enum_
  - `from` / `to` - Current (Cloud only): exact source/destination keys including descendants; supply both without `component`. Findings: one relationship, returning its full file list - _String_
  - `pageIndex` - Directives, findings or current from/to queries (Cloud only); integer starting at 1, default 1 - _Integer_
  - `pageSize` - Cloud only, integer: current from/to default/maximum 20; directives default/maximum 50; findings default and maximum 50, or 0 for count only - _Integer_

  Findings filters combine with AND. Each row contains `type`, `category`, `language`, `details` and `files`; findings have no ids. List pages keep at most 10 files and, for tangles, 10 node keys, and add `fileCount`/`filesTruncated` or `nodeKeyCount`/`nodeKeysTruncated` when a list is cut. A page that cuts any list sets `truncated` and explains how to read the rest. Pass `component` (a `nodeKey`, `fromNodeKey`, `toNodeKey`, or tangle node key) or both `from` and `to` to return the matching findings with their full lists. Page size defaults to 50 and cannot exceed 50; `pageSize` 0 returns the count only. Empty results mean no findings are visible, rather than proof that a project is healthy. Findings use Cloud organization and analyzed main-branch context, rejects incompatible category/type pairs before backend requests, refuses Findings reads before main-branch analysis, validates returned rows against active filters, identifies active filters for zero results, and gives a last-page hint. Unsupported future types, languages and deviation reasons are omitted with an explicit `skippedFindings` count only when they match any active filters; backend totals stay unchanged. Malformed known findings still fail, so omitted future rows do not imply a clean or complete analysis. A current graph with inconsistent node or edge counts, duplicate ids or keys, an edge to a missing node, or a file that has children and no separator is an API error. It is not reported as an empty architecture.

- **architecture_set** - Replace the whole intended model (Cloud and Server) or create, update and delete explicit project directives (Cloud only). For intended models, start from an unfiltered `architecture_get` response. Use `dryRun: true` to review changes. Hidden when `SONARQUBE_READ_ONLY=true`. OAuth requires both read and write scopes.

  Intended reads and writes use the public `project-intended-architectures` API. Preview an empty complete model before applying its DELETE. Applying a clear requires the revision from `architecture_get` with `target: intended`; that revision covers the whole stored model even when the read is filtered. A bare empty array cannot authorize deletion.

  **Directives:** Supply a JSON object with optional `create`, `update` and `delete` arrays. Create records contain directive fields, update records contain `{id, changed fields}`, and delete records contain only `{id}`. Unspecified update fields and unmentioned directives are retained. Creation skips duplicate operations. Preview with `dryRun=true` and apply only after confirmation. The whole batch is validated before writing; conflicting IDs are rejected. Writes are individual, not atomic. A partial or uncertain failure reports confirmed IDs and stops without retry or rollback. Duplicate checks and preflight reads can race concurrent edits. Optional fields cannot be cleared with null; the API has no conditional writes.

  Directive previews return proposed creates, changed values in `before` and `after` maps for updates (including an explicit null for a previously unset field), and delete targets without stored descriptions. Apply responses return counts and confirmed IDs without repeating the preview or description payloads. Unchanged fields remain on the server; no client replacement is inferred from summaries. New descriptions in create/update previews are shown in full. This reduces repeated content, but does not impose a byte limit on inputs or results.

  To change one description, read its `directiveId` if needed, then pass `model: "{\"update\":[{\"id\":\"<directive UUID>\",\"description\":\"New description\"}]}"` with `target: "directives"` and `dryRun: true`. After confirmation, send the same change file with `dryRun: false`. Other fields and directives remain untouched.

  Directive fields: `type` (`REMOVE_EDGE`, `RENAME_NODE`, `MOVE_NODE`), `ecosystem`, `graphType` (`file_graph`, `namespace_graph`), `fromNodeKey`, `toNodeKey`; optional `graphPerspective` (defaults to `default_perspective`) and `description`. Creation sets origin to `sonarqube-mcp-server`; updates preserve the stored origin. Identity comparisons normalize equivalent default perspectives without rewriting supplied values. For `MOVE_NODE`, `toNodeKey` is an existing destination container; for `RENAME_NODE`, it is the new complete key.

  **Validation:** The intended model is a JSON array of perspectives, or an object whose `models` array holds those perspectives. Unknown fields are rejected. Each perspective is `{type: file|namespace, language: java|cs|js|ts|py, label?, description?, groups, constraints}`. Each group is `{label, patterns?: [string], groups?, interface?: boolean, interfaceAccess?: boolean, description?, patternId?: uuid}`. Constraints are `{from, to}`. Labels are unique within a perspective and must not contain `/`. Constraint endpoints must name existing sibling groups; self-references and parent/child links are rejected. Descendants of an imported `patternId` group remain valid endpoints. Wildcard selectors are not group names. A changed model is also checked against available discovery data: exact container patterns and skipped physical parents produce warnings, without rewriting patterns or moving groups. Failed or missing discovery is reported as unchecked, not as a missing match. Exact leaf patterns and logical groupings remain valid. On SonarQube Server, that discovery check is skipped. A public read with a blank label, a `/` in a label, a duplicate label, or another incomplete group is reported as an incomplete intended architecture and is not exported.

  For physical models, read bounded current slices first and keep intermediate parents. For example, in a GCToolkit-style layout under `gctoolkit-parser`, nest `jvm` and `unified` inside `com.microsoft.gctoolkit.parser` and use `gctoolkit-parser:com.microsoft.gctoolkit.parser.**` for that subtree. Follow a single-child artifact chain to its branching point. Keep exact patterns for leaves and preserve discovery-binding patterns when moving or renaming groups. Do not infer physical structure from labels alone or replace user-requested logical groupings.

  **Data-loss limitations:** Omitted perspectives and groups are removed. Perspective labels, descriptions and imported pattern links are preserved when supplied in the exported model. Imported patterns remain references: keep any exported child groups unchanged or omit them; derived children are excluded from writes, and imported contents cannot be edited here. Partial views are rejected. An empty complete model deletes the stored intended resource after preview only when its exported revision is supplied. Supply the whole response to retain its revision check; concurrent edits can still race the check. Definite HTTP client rejections are relayed directly. An empty collection read after a failed DELETE response does not confirm deletion; the result reports that no model is visible and leaves the write unconfirmed. Uncertain writes return a recovery export when the desired state cannot be verified; no automatic rollback is attempted.

  Parameters:
  - `target` - Cloud: `intended` or `directives`; Server: `intended` - _Required Enum_
  - `projectKey` - The project key - _Required String_ _(Ignored when `SONARQUBE_PROJECT_KEY` is defined)_
  - `organization` - SonarQube Cloud organization key when none is configured - _Optional String, Cloud only_
  - `model` - Intended: whole unfiltered response or `models` array. Directives (Cloud only): `{create: [...], update: [...], delete: [...]}`, with fields listed above - _Required String_
  - `dryRun` - `true` to preview, `false` to apply - _Required Boolean_
  - `revision` - Intended only: exported revision; defaults to the whole response's revision. Required when applying a clear; other bare arrays without it cannot detect changes since export - _String_
