# Documentation

- Keep user setup and the concise tool reference in `README.md`; put design, rationale, recovery, and developer workflows in focused files under `docs/`.
- Document the behavior of the branch being delivered. Separate current behavior from proposed/unreleased backend support; remove obsolete pending-PR narratives when updating a section.
- Keep configuration, availability, input types/limits, and output examples consistent with code and tests. Do not repeat whole schemas in several documents.
- Link to canonical references rather than copying them. Check local links and examples after moving content.
- Instruction files follow [the instruction policy](development/agent-instructions.md); ordinary feature work does not require more rules.
